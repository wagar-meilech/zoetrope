# Codex agent visualization interfaces: third-party research

Researched 23 October 2026 against project documentation, source files, and release notes. No software was installed or exercised; capability confidence here means documentation/source confirmed, not a hands-on compatibility test. The user's later preference is terminal-first, with a separate companion window acceptable.

## Best matches

| Tool | Actual Codex subagent tree/graph? | Intervention | What its progress display means | Recommendation |
| --- | --- | --- | --- | --- |
| [Zoetrope](https://github.com/furkankly/zoetrope) | Yes: main session, nested subagents/workflow children, live terminal node graph | Read-only; continue steering in Codex | Activity/status, tool counts, output tokens; scrubber is session playback | Strongest match for an actual expanding graph inside a terminal |
| [AgentHUD](https://github.com/neochoon/agenthud) | Yes: expandable project → session → subagent tree and selected-node activity | Read-only; steer in Codex | Working/waiting and context-window occupancy | Strongest compact, keyboard-driven fleet overview |
| [agents-tree](https://github.com/blavka/agents-tree) | Yes: sessions and nested agents | Read-only; steer in Codex | Status, elapsed time, context use, tool details | Very lightweight alternative; Python only |
| [Agent Deck](https://github.com/asheshgoplani/agent-deck) | Managed sessions and parent relationships; automatic native Codex subagent discovery not established | Attach directly to the CLI; message composer/queue | Running/waiting/done, context/cost analytics | Better when managing and controlling many separate Codex sessions matters most |

**No verified candidate provides a dependable percentage of the user's whole goal completed.** Context occupancy, quota remaining, playback position, elapsed time, and “working” status answer different questions. A milestone checklist can support a useful completion indicator, but its quality depends on task decomposition, verification, and discovered work; an honest estimate can change as scope becomes clearer. This is an assessment of the inspected feature surfaces, not a claim that no such project exists anywhere.

## Zoetrope: first tool to try for the graph

Zoetrope explicitly supports Codex CLI and desktop-app transcripts, including subagents, live following, and replay. Its TUI graph has one node per agent, nested children, status/current tool/output tokens, tool chips, minimap, pan/zoom, and click-to-inspect prompts, model, and tool timings. `zoe` follows the current project's newest live session; `zoe <id>` selects a saved run; `zoe <file> --follow` tails its live edge. Native binaries exist for macOS, Linux, and Windows, with Homebrew and Cargo options. Its browser edition is an alternative, not a requirement. [Project README](https://github.com/furkankly/zoetrope#readme).

It is explicitly read-only. The timeline slider seeks through recorded events; pausing playback does not pause the agent. A Herdr integration can open the focused session's graph over its terminal pane with a keyboard shortcut and restore the pane when closed. Transcript formats are internal and may change. The project says it has no HTTP client in its native dependency graph. **Inference:** the observer itself needs no model calls or additional model tokens; steering still happens in the original Codex interface. [Usage, Herdr integration, architecture and limitations](https://github.com/furkankly/zoetrope#readme).

## AgentHUD: compact overview across projects

AgentHUD merges local Codex, Claude Code, Kiro, and OpenCode histories into a split-view terminal HUD. The upper panel is a project/session/subagent tree; the lower panel follows the selected node's current activity. Enter expands/collapses projects and sessions, and activity details open separately. A tracking mode follows newly active work. It requires Node 20+ for Codex; the README describes macOS/Linux as its primary development platforms. [README](https://github.com/neochoon/agenthud#readme), [keybindings](https://github.com/neochoon/agenthud/blob/main/FEATURES.md#keybindings).

Codex subagent support is substantiated beyond marketing: the provider parses separate rollout files, classifies subagents from session metadata, and nests them by `parent_thread_id`; older orphan formats are retained at the top level. The repository's empirical schema document includes a three-subagent sample and explains the links. The percentage beside each Codex row is recent request size divided by context window, **not task completion**. [Codex provider source](https://github.com/neochoon/agenthud/blob/main/src/data/providers/codex.ts), [Codex schema](https://github.com/neochoon/agenthud/blob/main/docs/schemas/codex-session.md).

The HUD/report/follow surfaces observe local files. No send, resume, or steer action is documented. **Inference:** normal observation adds no model tokens. The optional `agenthud summary` explicitly sends a report through an installed agent CLI, consuming model usage; a date-range summary can generate daily summaries and another synthesis. Cached prior-day summaries reduce repeat calls, while today's summary is regenerated. [Summary implementation behavior](https://github.com/neochoon/agenthud/blob/main/FEATURES.md#summary-daily).

## agents-tree: minimal dependency footprint

This terminal CLI uses Python 3.10+ with no external dependencies. `agents-tree --provider codex -w` watches Codex sessions; directory or session-ID targeting is available. Its tree includes nested subagents; selecting a row opens the spawn prompt, tools, last message, request/token counts, and transcript path. The publisher explicitly says the tool never talks to a session and nothing it prints enters an agent's context. This is particularly direct evidence for avoiding extra model-token overhead.

A limitation matters for Codex: all-session liveness is inferred from transcript writes in the last two minutes, so quiet sessions waiting for input may disappear until they write again. Explicit directory/session targeting still shows saved work. Large trees hide older finished agents. Herdr overlay integration is optional. [Publisher's PyPI documentation](https://pypi.org/project/agents-tree/).

## Agent Deck and other terminal session managers

Use the [asheshgoplani/agent-deck](https://github.com/asheshgoplani/agent-deck) project; several unrelated tools share the name. It manages terminal sessions, groups, worktrees, forking, cost displays, and native CLI attachment. The local message composer supports sending/queuing, but the README says non-Claude/OpenCode commands wait until the current turn finishes for queued messages: do not assume this is native Codex mid-turn steering. Attaching to Codex preserves Codex's own interactive behavior. Its optional Conductor is a persistent Claude or Codex agent that monitors other sessions and can respond/escalate; that adds actual agent work and model usage. Automatic native Codex child-thread discovery is not established by this review. [README and Conductor behavior](https://github.com/asheshgoplani/agent-deck#readme).

[Agent of Empires](https://github.com/agent-of-empires/agent-of-empires) is another maintained terminal-first choice: persistent tmux sessions, status detection, worktrees, optional containers, and optional browser/mobile views. Each managed agent is its own session, and native terminal attachment remains possible. This is session management rather than a verified map of Codex's internal subagent tree. [README](https://github.com/agent-of-empires/agent-of-empires#readme).

[Claude Squad](https://github.com/smtg-ai/claude-squad) also runs Codex despite its name: `cs -p "codex"`, independent git workspaces, session preview/diff views, attach to reprompt, pause/resume. It does not advertise a nested native Codex subagent graph. [README](https://github.com/smtg-ai/claude-squad#readme).

[dmux](https://github.com/standardagents/dmux) manages Codex and other agents through tmux panes/worktrees with pane switching, resume, and notifications. Optional AI naming, summaries, and pane analysis use an inference provider, so it should not be described as categorically zero-token. Its pane model is different from native subagent lineage. [README](https://github.com/standardagents/dmux#readme).

## Companion GUI options

- **[Agent Monitor, donvito](https://github.com/donvito/agent-monitor):** local Electron desktop graph, parent/subagent traces, per-agent/model token and API-equivalent cost breakdowns; Mac/Windows/Linux releases are currently unsigned. It reads Codex session files and distinguishes inactivity from explicit completion. No intervention controls are established. It is a young project; screenshots are synthetic demos. [README](https://github.com/donvito/agent-monitor#readme), [discovery/status semantics](https://github.com/donvito/agent-monitor/blob/main/docs/discovery-and-privacy.md), [usage/cost limitations](https://github.com/donvito/agent-monitor/blob/main/docs/usage.md).
- **[Agent Flow](https://github.com/patoles/agent-flow):** browser or VS Code interactive execution graph, session tabs, timeline/transcript panels, Codex rollout tailing and native token counts. Intervention is not documented. Its published standalone package has opt-out anonymous telemetry; VS Code and source-development runs do not emit it. The latest inspected release, v0.9.2 on 9 October, fixes hook preservation and background-subagent completion bugs. [README](https://github.com/patoles/agent-flow#readme), [releases](https://github.com/patoles/agent-flow/releases).
- **[ccdeck](https://github.com/BarganConstantin/ccdeck):** local browser/desktop canvas, tool calls, usage and quota. Its specific Codex guide and current README say explicit Codex parent links create child cards; the homepage FAQ contradicts this by calling subagent cards Claude-only. Treat Codex tree support as documentation-confirmed but requiring compatibility validation. Codex approvals/waiting signals are unavailable, and the product explicitly cannot steer agents. [Codex guide](https://ccdeck.dev/guides/codex/), [contradictory homepage FAQ](https://ccdeck.dev/#questions), [README](https://github.com/BarganConstantin/ccdeck#readme).
- **[CodexMonitor, Dimillian](https://github.com/Dimillian/CodexMonitor):** a richer app-server frontend with stop/interrupt, explicit Queue/Steer follow-ups, plans, approvals, worktrees and context meters. Its main organization is projects/threads, not a verified node graph; it is less aligned with the terminal preference. [README](https://github.com/Dimillian/CodexMonitor#readme).

## Practical recommendation

Keep Codex as the control surface and open **Zoetrope** in a neighboring terminal pane for the graph. Choose **AgentHUD** instead when an expandable text tree across projects is preferable. Both let observation stay out of model context; feedback still goes through Codex. Add a session manager only if switching among many independent terminals becomes the main problem. Avoid enabling LLM digests, conductors, or AI pane analysis until their additional value is useful enough to justify the model usage.

The missing piece is reliable goal progress: ask for a small milestone plan with concrete completion checks and visible completed/remaining items. That can give a useful progress count without continual “estimate your percentage” model calls. Treat both milestone counts and estimates as revisable when new work is discovered.
